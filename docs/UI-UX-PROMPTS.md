# 枪战突击 · 商业级 UI 优化提示词集

> 用法：每个提示词独立可用（含上下文，无需会话记忆）。逐条执行，按提示词内附带的验收标准自检。
> 全局约定：样式只追加到 `#ui-v2` 末尾；不改数据绑定字段名；每个提示词完成后必须走
> `docs/PLAYBOOK.md` 的验证四步（锚点唯一 → 两段式补丁 → 语法/结构计数 → 无头浏览器逐屏截图）。

## 01 · 设计系统总纲（先做，其他提示词都依赖它）

```
本项目是单文件 Three.js FPS 游戏（index.html，约 4.8 万行，样式只允许追加到 <style id="ui-v2"> 末尾）。
请把现有 UI 的设计令牌层升级为商业级 FPS 标准，对标《Apex Legends》《Valorant》《CODM》：

1. 重建 :root 设计令牌：6 级文字灰阶、3 级面板材质（基色/浮起/凹陷）、3 级边框、
   3 级阴影高度、统一圆角梯度（4/8/12/16/24）、统一间距梯度（4/8/12/16/24/32/48）、
   语义色板（成功/警告/危险/信息）与三色强调体系（主=青、次=品红、三级=紫），每个色给 4 个透明度档。
2. 排版体系：5 级字号 + 3 档字重 + 2 套字体（展示用 Orbitron、界面用 Rajdhani），
   数字一律 tabular-nums，眉标类文本统一大写 + 0.2em 字距。
3. 动效令牌：3 档时长（120/200/340ms）+ 2 套曲线（标准 / 出场缓动），所有过渡必须引用令牌。
4. 输出一份「令牌使用对照表」追加到 docs/ARCHITECTURE.md。

验收：无头浏览器截首页/仓库/商城/设置四屏，肉眼对比无明显塑料感；
所有新样式在 #ui-v2 中且不改旧层；8 个 script 块 0 语法错；页面 0 运行时错误。
```

```

   右侧角色/出战展示；底部版本信息。

CTA 在首屏内；改动只追加到 #ui-v2；0 语法错；0 运行时错误。
```

## 10 · 战斗反馈系统（打击感核心）

```
打击感是 FPS 的灵魂。请建立统一的战斗反馈系统：

1. 命中反馈：命中不同部位有不同命中标记（普通/暴击/爆头三种准星扩散样式 + 配色）。
2. 击杀确认：击杀时准星中心短暂收缩 + 「击杀」小字 + 连杀计数在准星下方滚出。
3. 伤害数字：按伤害量分级字号与颜色（白/黄/橙/红），暴击带描边并轻微上浮。
4. 受击方向指示：受击时屏幕边缘出现来源方向红色扇形指示（1s 淡出）。
5. 全部反馈元素走对象池，禁止每帧创建 DOM。

验收：连续射击时反馈元素不闪烁、不重叠；1 分钟高强度战斗内存稳定；
对象池实现；0 语法错；0 运行时错误。
```

## 15 · 全局动效规范落地

```
把动效令牌（01 的产物）落地到所有交互元素：

1. 按钮：hover 上浮 1px + 边框提亮；active scale(0.985)；焦点 focus ring 2px。
2. 卡片：hover 上浮 3px + 阴影加深 + 边框提亮；入场 stagger（每项延迟 40ms）。
3. 弹窗：背景模糊渐入 + 内容 scale(0.96→1)；关闭反向。
4. 列表增删：FLIP 动画（高度过渡）。
5. 全局遵守 prefers-reduced-motion（动效全部降级为直接切换）。

验收：抽查 10 类交互元素的动画时长/曲线与令牌一致；
开启系统「减少动态」后无动画；0 语法错；0 运行时错误。
```

## 18 · 性能与可访问性

```
1. 性能预算：UI 层每帧不触发 layout thrash（批量读写分离）；动画只用 transform/opacity；
   事件节流（resize/scroll）。
2. 可访问性：所有可交互元素可 Tab 聚焦 + 可见 focus ring；色彩对比度 ≥4.5:1（用工具扫一遍）；
   弹窗 Esc 可关、焦点圈定在弹窗内。
3. 图片/纹理懒加载与销毁（切场景 dispose）。

验收：Performance 面板录制 30s 战斗无 layout 抖动红线；
Tab 可走完整个设置页；色彩对比度报告达标；0 语法错；0 运行时错误。
```
