## 15:45 — 修复：伙伴「叶夕水」实战中播的是波塞西那套技能
### 根因（不是接线错，是**实现解析**错）
- 技能选择链路本身正确：`companionSkillPool(def)` 取她自己的 9 技（名字/系数/魂环都对）→ 杀手播报也显示她的技能名。
- **但技能实现只按 `sk.kind` 去查通用原型表 `COMPANION_SKILL_KINDS`**。她 9 技里 **7 个 kind 与波塞西重叠**（meteor / barrage / spear / domain / vortex / transform / verdict）→ 视觉与手感完全就是波塞西那套（同样的锥体、同样的线形 AoE、同样的三叉戟+领域）。
- 对比：副本 BOSS 侧早有 11 个**专属** `RAID_SKILLS` 实现（血雨锥/骨柱地狱之门/十二血翼/血海/死神之光），伙伴侧却共用通用原型 → 两边不一致。

### 修复
- 新增 **`COMPANION_SKILL_BY_ID`**（按**技能 id** 索引的专属实现表，11 条），解析改为
  `const fn = COMPANION_SKILL_BY_ID[sk.id] || COMPANION_SKILL_KINDS[sk.kind];`（魂技循环与死神塔循环各一处）→ **专属实现优先，通用原型兜底**（波塞西等其它伙伴零改动）。
- 新增血色视觉辅助：`_compBloodPillar`(能量柱) / `_compBloodWave`(扩张血环+血雾) / `_compBloodDrops`(坠落血锥) / `_compPierceLine`(**单次结算**的直线穿透，替代原先"沿直线丢 10 次 AoE 导致同一敌人被重复结算"的写法) / `_compBloodAura`(血翼光环) / `_compSetBuff` / `_compTgtPos`。
- `companionTrack` 扩展两个动画字段：`vy`（坠落）与 `grow`（扩张/收缩环，负值即收缩）。
- 11 技逐一对齐副本版本：血雨三波 / 6 只不死魔傀扑击 + 环形亡灵冲击 / 血魂巨锥贯穿 / 地狱之门（黑盘+门环+12 骨柱+5 次汲取） / 14 圈收缩血环抽血 / 血色能量柱强化 / 十二血翼血魂真身 / 空间撕裂+瞬移+三段斩 / 血海（r18 血盘+血墙+汽化+6 次汲取） / 死神之光 74m 横扫 / 死亡领域（r16 五环+4 次汲取）。

- 逐技实放：敌人掉血 ✓、控制（stun 0.8~2.5 / slow 2.6）✓、增益（mult 2.5 / dr 0.85 / aura 2.5 或 1.6/0.5）✓，11 技 0 报错

### 教训

### 顺带修掉两个真 Bug
1. **3 处 `})(ii);` 笔误**（应为 `})(i);`）→ IIFE 传参写错，整段技能抛 `ii is not defined`（副本 blood_transmute、伙伴 blood_transmute / sea_god_doom 全失效）。
2. **玩家在领域 DoT 中阵亡会崩溃**（原有隐患）：`playerTakeDamage` → `playerDie` → `raidEndRun` → `raidResetState()` 把 `raidFx/raidWarns` **换成新数组**，而 `raidUpdateFx`（含 `_raidFxExtPatch` 包装层）仍按旧下标访问 → `undefined.kind` 抛错。修复：循环前捕获数组引用 `_arr`，`if (!f) continue/break` 兜底 + 引用变化即中止本帧。

### 教训
- 手写 `(function(ii){...})(ii)` 这类 IIFE 传参极易写错 → **for 变量名与 IIFE 形参名不要同名**，或直接别用 IIFE（改用 `let` 块作用域）。
- **「回调里可能重置整个场景」必须视为常态**：任何按数组下标遍历 + 回调内可能 `playerDie`/场景重置的系统，都要先捕获引用并在引用变化时中止，否则读到 `undefined` 崩溃。
