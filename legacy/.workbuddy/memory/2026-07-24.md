## 修复：商城页面点开后空白（bug）
- 现象：用户点击「商城」进入商城页面后内容空白。
- 根因（两处，缺一不可）：
  1. **主页入口 `homepage-shop-btn`（#homepage-shop-btn，底部 dock 🛒）的点击处理函数只设 `shopModal.style.display='flex'`，从不调用 `buildShop()`**；而 `buildShop()` 才是真正往 `#shop-items-container` 灌卡片的函数（in-game 的 `open-shop-btn` 会调，主页入口不会）。所以主页点开 = 空容器 = 空白。
  2. **boot 期 `buildShop()` 抛 TDZ**：`WEAPON_CATALOG` 的 getter（`get baseDmg(){ return THUNDEREX_BASE_DMG }` 等）引用在 initAll 后半段（~L26821）才声明的武器基础伤害常量；boot 期 `buildShop()` 在常量初始化前同步执行 → `ReferenceError: Cannot access 'THUNDEREX_BASE_DMG' before initialization` → 被 try/catch 吞掉，商城从未在 boot 期预渲染。任何不自己调 `buildShop()` 的入口都会空白。
- 修复（已部署 + 线上 puppeteer 验证通过）：
  - Fix A：`homepage-shop-btn` 处理函数先 `buildShop()`（try/catch）再显示弹窗，与 `open-shop-btn` 对齐。
  - Fix B：boot 期 `buildShop()` 改为 `setTimeout(...,0)` 延迟到 initAll 同步执行完毕（所有武器常量已赋值）后再渲染，消除 TDZ 报错并使预渲染可靠。
  - 附带修：`updateShopState()` 内大量遗留 `buyXxxBtn.textContent` 引用在 init 早期捕获为 `null`（boot buildShop 不再同步建按钮），调用即抛未捕获异常；改为只保留其下方已有的、数据驱动的 `.shop-buy-btn` 遍历逻辑（覆盖全部武器含 thunderex），删除死代码。
- 验证：`node --check` 5 段 inline script 全过；线上 http://182.92.179.201:3000/ 注册测试号 → 主页 dock 🛒 与 in-game open-shop-btn **两条入口均 21 件、全部可见、内容高度 6766、SHOP_ERRS=[]、PAGEERRORS=[]**。

## 测试方法论（重要·可复用）
- **initAll 登录门控**：游戏把 initAll/registerStartScreenButtons/character-init 通过 `window.__fpsGate` 推迟到 `unlockBoot()`（登录后）。puppeteer 直接加载时不运行 init，故 `window.WEAPON_DISPLAY_DATA` 等未暴露。测试时手动：`window.__fpsBootState='unlocked'; const q=window.__pendingBoots||[]; window.__pendingBoots=[]; q.forEach(fn=>{try{fn()}catch(e){}});` 即可触发 init。
- **闭包作用域**：几乎所有游戏函数/状态（startLevel/tianfaShoot/enemies/ownedWeapons/equippedPrimary 等）都在大 IIFE 内，非 window、bare 也访问不到。要驱动战斗只能：临时加 `window.__xxxQA={...}` 钩子暴露闭包函数（测后务必移除并重新部署），或走真实 UI 登录流程。
- **headless WebGL**：默认无 GPU，THREE.WebGLRenderer 创建失败导致 initScene/initInputHandlers 抛错。启动 puppeteer 加 `--enable-unsafe-swiftshader --use-angle=swiftshader --use-gl=angle` 即可软渲染通过。（`bindPCGuard is not defined` 是**预存 bug**，L34432 调用但未定义，被 boot try/catch 吞掉，非本次引入，不影响 initAll。）

## 修复：天罚·神裁之眼 上线后严重 BUG（冷却卡死/无伤害数字/卡顿）
- 现象（用户反馈）：技能冷却异常卡住不动；普攻与技能均无法使用；伤害数字显示异常；需保证流畅。
- **根因（单个致命缺陷）**：三个冷却变量 `tianfaShootCooldown / tianfaCompressedCooldown / tianfaDomainCooldown` 只在 tianfaShoot/compressed/activateTianfaDomain 里被**置位**，却**没有任何地方递减**（其他武器都在主循环 L31490-31525 区块逐帧 `Math.max(0,cd-delta)` 递减，tianfa 漏接）。而 `updateTianfa` 在域未激活时 `return` 早退，更不可能递减。结果：首次开火后 cooldown 永久 >0 → 每次 tianfaShoot/compressed/domain 都因 `cd>0` 早退，普攻与技能全部失效。
- **修复 1（冷却）**：在主循环武器冷却递减区（thunderex 之后）补三行 `tianfaShootCooldown/CompressedCooldown/DomainCooldown = Math.max(0, cd-delta)`（与全游戏一致）。
- **修复 2（伤害数字 + 流畅）**：`tianfaHitEnemy` 加 `opts.silent`；星云/领域持续 AOE 改为**累计伤害 + 每 0.25s 弹一次数字**（原每帧弹一次，`220*delta≈3.5` 的抖动点数字既难看又刷满全局每帧飘字上限导致卡顿）。离散命中（左键/落雷/领域落雷）仍实时弹字。
- 验证（临时 QA 钩子驱动，测后移除）：node --check 全过；确定性 tick 证明三冷却均可递减且归零（shoot 0.083→0 / compressed 2→1.5 / domain 14→12→0）；活跃主循环中 domCd 14→13.195 实际递减；连续开火+领域 **PAGEERROR/CONSOLE ERROR=0**。已重新部署，钩子 `__tianfaQA`=0、tianfa 数据 intact。
- **测试坑（重要）**：headless 在 `await sleep()` 纯空闲期会**节流 rAF**，使主循环暂停 → 冷却看似"卡住"。验证冷却务必用确定性 `tick(dt)` 或保持页面活跃（频繁 evaluate），否则会误判为未修复。
