## 紧急修复：E→中键改键导致的两个线上 BUG（17:xx）
- BUG1「所有按键无法攻击」根因：上轮在主 mousedown 监听开头加 `if(_keybindCaptureAction) return;`，但 `_keybindCaptureAction` 定义在设置面板作用域(L4934)，与游戏输入作用域(L21446)是不同 IIFE，裸引用会抛 ReferenceError，导致每次鼠标按下监听一进函数就崩溃 → 左键/右键/中键全部失效。修复：统一改为 `window._keybindCaptureAction`（声明+全部 10 处引用），跨作用域可见；同时删掉了上一轮品级体系遗留的 `window.__tierQA` 调试钩子。
- BUG2「中键技能仍显示E触发说明」根因：技能面板 `getCurrentWeaponSkills()` 里 16 个中键技能的 `key:'E'` 字段是裸字符串，上轮文本补丁只覆盖了 `[E]`/`(E)`/`E键` 等带括号/汉字形式，漏掉了这种。渲染处(L26115)用 `[${sk.key}]` 显示触发键 → 卡片显示「E」。修复：在 `getCurrentWeaponSkills` 内新增 `WSK_TRIGGER` 动态取 `window._keyDisplayName(window._getKeymap().weaponSkill)`（默认兜底'中键'，并把'鼠标中键'压成'中键'与底部HUD卡一致），16 处 `key:'E'`→`key:WSK_TRIGGER`，改键后自动同步。
- 验证：5 段 `node --check` 全 OK；本地+线上无头 boot 0 error；派发 mousedown(button0/1/2) 不再抛错；`weaponSkill==='Mouse1'`、`disp==='鼠标中键'`、`captureFlag===null`；线上 grep `key:'E'`=0、`[E]`=0，HTTP200。已部署 pm2 restart fps-arena。
