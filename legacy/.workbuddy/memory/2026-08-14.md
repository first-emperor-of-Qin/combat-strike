## 游戏菜单触发改为「ESC 释放鼠标后按右键」（取代上一节）
- **需求**：玩家首次按 ESC 释放鼠标后，改为**按右键**显示菜单「重新开始」「退出当前关卡」，战斗继续，无需再次按 ESC。
- **改动**：
  - `case'pause'`(L23186) 指针锁定分支回退为**仅** `document.exitPointerLock();`（去掉上一节加的 `openEscMenu()`）；`escMenuOpen` 时 ESC 仍关闭菜单，未锁定时 ESC 仍可开菜单（保留为兼容路径）。
  - `contextmenu` preventDefault 之后（L23229 段）**新增独立 `mousedown` 监听**：`e.button===2` 且 `!isPointerLocked && gameStarted && !isDead && !levelComplete`，并排除 `escMenuOpen/isPaused/isPanelOpen` 与各弹窗（`#pause-menu,#esc-menu,#death-screen,#victory-screen,#player-panel,#levelselect-modal,#skip-wave-modal,#shop-modal,#buy-confirm`）→ `openEscMenu()`。
  - **关键隔离**：既有游戏内 `mousedown` handler 首行 `if(!isPointerLocked...) return;`，故锁定态右键仍走武器特殊功能（开镜/破鸿之翼等），互不干扰。右键不触发 `click` 事件（只触发 `auxclick`），因此不会误触「点击画面重新锁定指针」逻辑。
  - 文案同步：pauseHint 副文案 → `点击画面继续操控 | 右键打开菜单（重新开始 / 退出当前关卡）`(L23250)；about 操作说明(L3675)、首页操作速查(L3953) 的「ESC — 暂停」→「ESC — 释放鼠标（释放后按右键打开菜单…）」；`escMenuOpen` 声明注释(L9148) 与 ESC 菜单区块注释(L23285) 同步。
- **验证**：`/tmp/check_syntax.py` 7 OK/0 FAIL；`grep "document.exitPointerLock(); openEscMenu();"`=0。无头 QA(`/tmp/qa_esc_rightclick.js`) **13/13 通过**——首次 ESC 不弹菜单且不暂停、提示文案含「右键打开菜单」、右键→menu flex&open&isPaused=false&pauseHint none、菜单按钮文案正确、菜单已开时右键幂等、ESC 可关闭、**锁定态右键不弹菜单**、右键可重复触发、0 page/console error。临时 `__QA` 钩子已删(grep=0)。
- ⚠️ **QA 时序坑**：无头下用 `Object.defineProperty(document,'pointerLockElement',...)` 伪造锁定**不会**置 `pointerLockAcquiredOnce=true`，`pointerlockchange` 会走「准备就绪/点击画面开始游戏」分支而非「已释放鼠标」分支 → 校验 pauseHint 文案会假失败。正确做法：先 `_fakeLock(true)` + 手动 `dispatchEvent(new Event('pointerlockchange'))` 走一遍「获得锁」分支，再解锁复现真实文案。
