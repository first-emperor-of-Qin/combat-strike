1. patch4 的 `OLD_CARD2` 锚点匹配到 `.v-modes` 闭合 `</div>`，导致 dodge-mode-btn 被插入到 `.v-modes` 外面，并多出一个 `</div>` —— 破坏首页容器结构（**与上次 arena 修复完全相同的坑**）。
2. 即便 DOM 修好，CSS 也出问题：老版首页用 Bento 布局，规则 `#level-select-btn { grid-area: level !important; }`（L1989）在 `.start-btns` 里给 level-select 分配命名区域。这个 ID 选择器**全局命中**，在 `.v-modes` 里也生效 → 浏览器隐式创建名为 "level" 的 grid area + 2 个额外轨道 → 关卡选择被挤到列 5 换行。
3. `.v-mode-card { min-width: 340px }`（L91）撑破 `minmax(280px, 1fr)` 的最小轨道约束。

### 问题 2：局内首页模块泄漏
**根因链**：
- startLevel 内部有异步逻辑会**重新显示** start-screen（即使 startDodgeMode 已经隐藏）。
- 仅有 `startScreen.style.display='none'` 不够，startLevel 内部的延迟回调会覆盖。

## 经验（重要）
- **`!important` 在媒体查询内必须重复声明**：上一轮 `repeat(auto-fit, ...)` + `@media (min-width:1200px) repeat(3,1fr)` 没生效的元原因不是 CSS 优先级，而是 `.v-mode-card min-width:340px` 撑破 grid track minmax(0,1fr) 仍然有效（0.4 才有 0 这个灵活性）。诊断用 `getComputedStyle().gridTemplateColumns` 时 auto-fit 会展开所有隐式轨道，5 列字符串（290 290 290 0 228）就是这种伪信号。
- **ID 选择器全局污染**：用 ID 设 `grid-area: X` 时，**任何**上下文里的同名 ID 都被命中；老页面（Bento）→ 新页面（v-modes）迁移时必须重置。诊断用 `getComputedStyle(child).gridArea` 暴露污染源。
- **`hide / restore` 必须成对**：只隐藏不恢复会导致"再回来时整页错乱"（这是新坑，比"局内泄漏"更隐蔽）。直接用 `style.removeProperty('display')` 而非 `style.display = ''`，避免重置为 `''` 与 `'none'` 比较的真值陷阱。
- **可见性 QA 检测要用 `getBoundingClientRect().width > 0`**：之前用 `getComputedStyle(el).display !== 'none'` 会误报：父级 `display:none` 时，子元素 computed display 仍是自己原值（如 flex），但视觉上不可见 —— QA 报"泄漏"其实是误报。
