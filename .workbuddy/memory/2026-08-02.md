## 大数单位换算 BUG 修复（血量/伤害显示）
- 现象：`formatCN`（玩家/共享血量，L22116/L9788）与 `formatDamageNumber`（伤害飘字，L21666）原有“向上进位”逻辑：当某单位值≥1000 时跳到上一阶单位，但上一阶单位的值往往 <1，导致出现**小数高阶单位**（如 6.5e11 → "0.65兆"、1.234e11 → "0.12兆"）。这违背“只有达到该单位整数基准(≥1×单位)才进位”的规则。
- 修复：两函数均改为「仅当 n ≥ 该单位基数(1e12=兆 / 1e8=亿 / 1e4=万)时才用该单位」，去掉进位分支；不足1万直接显示整数。结果：0.65兆→"6500亿"、1万亿→"1兆"、1.234e11→"1234亿"。
- 验证：`/tmp/qa_fmt.js` 无头 QA 11/11 通过、0 报错；`/tmp/check_syntax.py` PASS 6/6。已部署（scp + pm2 restart）。
- 其他格式化函数（`formatDamageStat` DAMAGE_UNITS、`formatHP`/`formatHP2` boss血条、`formatDamage` 联机伤害榜）本就按阈值(=基数)判断，无此 BUG，未改。
