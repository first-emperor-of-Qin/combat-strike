## 功能：BOSS血条分割为100个独立小段（每段=1%血量）
- 用户要求：BOSS血条拆成100段，每1%对应一段，HP每减少1%即切换下一段，共显示100段。

### 实现思路（遮罩叠加，复用既有逻辑，避免回归）
- 既有 `updateBossBar()` 用连续 `#boss-bar-fill-inner`（width=pct）显示血条，并带颜色阶段(hp-high/mid/low)、伤害延迟条、低血脉冲。直接替换连续条风险大。
- 采用「遮罩叠加」：在 `#boss-bar-frame` 内新增 `#boss-bar-segments`（绝对定位覆盖填充区，z-index:3，flex 100 个 `.boss-seg` 单元，段间 `inset -1px` 描边分隔）。满段=透明（透出底部连续填充色），空段=暗色遮罩。这样颜色/伤害/脉冲全部沿用旧逻辑，仅叠加分段视觉。
- 新增 `_syncBossSegments(container, filledCount)`：首次 lazy 建 100 个 `.boss-seg`；用 `container._lastFilled` 缓存，整数百分比未变则不重绘（受击极高频，避免每发子弹都操作 DOM）；仅 `i<filledCount` 加 `filled` 类。
- `filledCount = Math.max(0, Math.min(100, Math.ceil(pct*100 - 1e-6)))`：用 ceil+epsilon，使「每减少1%即熄灭一段」精确成立（100%→100段，99%→99段，…，0%→0段；边界用 1e-6 防止浮点把 99.0 误算成 100）。已写 node 脚本验证：100%→0% 共 100 次切换、无跳变。
- 双BOSS(boss2) 同样处理：`#boss2-bar-segments` + 在 `updateBoss2Bar()` 内调用同一 `_syncBossSegments`，引用变量 `boss2BarSegments` 并入既有 `let boss2Bar...` 声明并在 init 块赋值。

### 改动文件位置
- CSS：L435 区域 `.boss-seg`/`.boss-seg.filled`/`#boss-bar-segments,#boss2-bar-segments`（遮罩+flex+段间描边）。

## 修正：BOSS血条应为100条「独立完整血条」，非单条细分
- 用户澄清上一版理解有误：他要的不是“一条血条划成100格”，而是**显示100条独立完整的血条**，BOSS每损失1%移除一整条，直至100条全消失。
- 已回退上一版的「遮罩叠加分段」方案（`#boss-bar-segments`/`.boss-seg`/`_syncBossSegments` 全部删除），改为**侧边阶梯（ladder）**：
  - 新增 `#boss-bar-ladder`（左侧 fixed）/ `#boss2-bar-ladder`（右侧 fixed），各含 100 个 `.boss-ladder-bar`（每条=1%血量，独立完整样式：边框+红渐变填充+辉光；boss2 用蓝边框区分）。
  - `_syncBossLadder(container, filledCount)`：懒建 100 条，`_lastFilled` 缓存避免高频重绘；`i<filledCount` 显示、否则加 `.empty`(`display:none`)，即“移除一条”。
  - `filledCount = Math.max(0, Math.min(100, Math.ceil(pct*100 - 1e-6)))`（与之前同一数学，已验证 100%→0% 恰好 100 次切换）。
  - 原单条连续血条 `#boss-bar-frame`/`#boss2-bar-frame` 与 `#boss-bar-ticks`/`#boss2-bar-ticks` 用 `display:none !important` 隐藏（避免与100条并存）；顶部中央仍保留 boss 名称+HP数值文本做读数。
  - 双BOSS：boss1 左侧阶梯、boss2 右侧阶梯。
- 布局用 `position: fixed` + `vh` 单位自适应：每条高 `0.58vh`（min 2px），100 条约占 72vh 居中，不遮挡屏幕中央。
- 校验/部署同前：5 段 inline `node --check` 全过；SCP + `pm2 restart fps-arena`（online）；curl 确认 ladder 容器/`function _syncBossLadder`/两处调用/隐藏规则均在场，且旧 segments 代码 0 残留。
- 注：BOSS 头顶的 3D 浮动血条精灵（`createHealthBarSprite`）未改，仍是一条；若用户也要改成100条需另行处理（当前范围只覆盖 HUD 顶部血条）。

## 修正×2：BOSS血条应「每次显示一条完整满格血条，每损失1%换入下一条」（非连续收缩）
- 用户第三度反馈：上一版（C-rev2）保留连续 width=pct 收缩 + 仅加淡入动画，看起来仍像“逐段减少”，**不是**“每损失1%替换为下一条全新的完整血条”。
- 真实含义（已落实到代码）：100条独立完整血条，**每次只显示一条，且这条始终是「完整（满格）」血条**；BOSS每损失1%就把当前这条完整血条替换为“下一条全新的完整血条”（重放一次换入动画）。血条本身**不随剩余血量收缩**。
- 改动（updateBossBar / updateBoss2Bar 两处一致）：
  - 删 `bossBarFillInner.style.width=(pct*100)%`，改为恒 `style.width='100%'`（始终满格完整血条）。
  - 删「伤害延迟条」的 `width=calc(...)` 计算（主条恒满格，延迟条无意义），改为 `style.width='0%'` 占位。
  - 换入逻辑不变：`_b1idx/_b2idx = clamp(0..100, ceil(pct*100 - 1e-6))`；`_idx < 缓存` 时 `_triggerBossBarSwap(fillInner)`（remove class→void offsetWidth 重排→add class 重放动画）；`_idx > 缓存` 重置基准（满血/回血）。
  - HP 文本加进度计数：`'血条 ' + _b1idx + '/100 · ' + formatHP(...)`，让玩家看到当前显示的是第几条/共100条（满血100/100，死亡0/100）。
  - 颜色阶段(hp-high/mid/low)、低血脉冲保留，随剩余 pct 变色，作为额外反馈。
  - CSS `@keyframes bossBarSwapIn` 改为从 `translateX(-100%)` 滑入（0.28s），更像“一条新血条从左滑入替换旧条”。
- 校验：5 段 inline `node --check` 全过。部署：SCP + `pm2 restart fps-arena`（online）。curl 验证 `血条 ' + _b1idx + '/100` 与 `style.width = '100%'` 在场、旧收缩逻辑 0 残留。线上 http://182.92.179.201:3000/。
- 教训：用户说“完整血条/替换为下一条”时，**血条宽度必须恒为满格**，绝不能用剩余血量比例去收缩——收缩即被理解为“逐段减少”。进度用「第 N/100」计数表达。

## 修正×3：BOSS血条必须是“100格分段血条，掉血时红色可见减少”（满格恒红=看不出掉血）
- 用户第四度发飙：上一版（修正×2）把血条做成“恒定满格红 + 换入动画”，结果**永远满红、看不出掉血**，与“每1%是一条完整血条、应可见掉血”矛盾。
- 关键洞察（spec 内部自相矛盾，必须二选一）：要“可见掉血”就绝不能恒定满格；唯一能同时满足“可见掉血 + 100条完整1%血条”的呈现 = **单条横条内排 100 个独立完整小格（.boss-seg）**：满血=100格全红；每损失1%最右侧一格（=一条完整血条）熄灭变暗，红色肉眼可见减少。
- 实现（updateBossBar / updateBoss2Bar 两处一致）：
  - HTML：frame 内新增 `<div id="boss-bar-segments">` / `<div id="boss2-bar-segments">`（绝对定位覆盖填充区，flex 100 格）。
  - CSS：`.boss-seg` 暗底、`flex:1`；`.boss-seg.filled` 满红渐变+辉光；`@keyframes bossSegFlash` 亮度闪一下；`.boss-seg-swap` 应用。
  - JS：`_syncBossSegments(container, filledCount)` 懒建 100 格，`container._filled` 缓存（整数百分比未变不重绘，避免高频受击狂刷 DOM）；`i<filledCount` 加 `filled`、否则移除；仅当 `filledCount < _filled`（掉血）或首帧播放 `boss-seg-swap` 闪光，表示“替换为下一条完整血条”。
  - 连续填充 `#boss-bar-fill-inner` 设 `width='0%'` 隐藏（改由分段格呈现掉血，避免背后透红）；伤害延迟条 width=0 占位；低血脉冲保留在整框。
  - 进度计数 `血条 N/100` 保留（N=filledCount）。
- 校验：5 段 inline `node --check` 全过。部署：SCP + `pm2 restart fps-arena`（online）。curl 确认：boss 双条 fill width='0%'、`_syncBossSegments` 定义+两处调用、`boss-bar-segments` DOM+CSS 均在场，旧满格/`_triggerBossBarSwap` 0 残留。
- **铁律（务必记牢，避免再被骂）**：BOSS血条的“100条完整血条”= **一条横条内的 100 个分段小格，满血全红、掉血逐格变暗（红色必须可见减少）**。**绝不**做成“恒定满格红”（那是修正×2的失败版，用户大怒）。每次改动后必须 curl 验证 `bossBarFillInner.style.width='0%'` 且分段逻辑在场。

## 修正×4：BOSS血条终极正确理解——“单条完整血条被耗尽即切换到下一条满血条”
- 用户第五度怒骂，并给出唯一准确描述：“boss每1%的血量是一整条完整的血条，一条血条被耗尽，就切换另一个满血的1%血量的血条，直至boss死亡。”
- **正确模型（之前 4 版全错）**：100 条独立完整血条，每条 = BOSS 总血量的 1%。**任意时刻只显示一条**（单条完整血条，外观如原单条血条）。当前这条代表 BOSS“当前这 1% 血量”，它是一条完整血条，**随该 1% 被消耗而从满格逐渐耗尽（可见掉血）**；该条被耗尽（掉到空），即**切换到下一条“满血”的 1% 血条**（重放换入动画）。如此 100 条依次切换，直至 BOSS 死亡。
- 数学：
  - `_lost = (1 - pct) * 100`（已损失百分比 0..100）
  - `_chunk = clamp(0,100, floor(_lost + 1e-9))`（当前正在耗尽的是第几条，0-based）
  - `_remain = clamp(0,1, 1 - (_lost - _chunk))`（当前条剩余比例，0..1；满血=1，耗尽=0）
  - 满血：`_chunk=0,_remain=1` → 条满；耗 0.4% → `_remain=0.6` 条在 60%；耗满 1% → `_chunk=1,_remain=1` 切换到下一条满血条；死亡 `_chunk=100`。
- 实现（updateBossBar / updateBoss2Bar 两处一致）：
  - 删掉 100 格分段的 `#boss-bar-segments`/`.boss-seg`/`_syncBossSegments` 全部代码（那是修正×3，用户说“同时显示/不是完整血条”仍不对）。
  - 复用单条 `#boss-bar-fill-inner`：`style.width = (_remain * 100) + '%'`（随 1% 耗尽而 drained，可见掉血）。
  - 缓存 `_bossBarChunk`：当 `_chunk > _bossBarChunk`（一条被耗尽）→ 更新并 `_triggerBossBarSwap(fillInner)`（重放左滑换入动画，表现“切换到下一条满血条”）；`_chunk < _bossBarChunk` 视为回血重置。
  - 还原 `bossBarSwapIn` 关键帧 + `.boss-bar-swap-in` 规则（作用于 fill-inner）；还原 hp-high/mid/low 颜色阶段（按整体 pct）。
  - 低血脉冲保留在整框；伤害延迟条 width=0 占位。
  - 计数文字 `血条 (100 - _chunk)/100`（剩余完整血条数）：满血 100/100，死亡 0/100。
- 校验：5 段 inline `node --check` 全过。部署：SCP + `pm2 restart fps-arena`（online）。curl 确认：`_remain1 * 100` / `_triggerBossBarSwap(bossBarFillInner)` 在场、分段/100格代码 0 残留、`bossBarSwapIn` 关键帧在场。
- **最终铁律（替换上面那条）**：BOSS“100条完整血条”= **单条完整血条，代表当前 1% 血量，随该 1% 被消耗而从满格 drained 到空；耗尽即切换到下一条满血条（换入动画）；共 100 条依次切换至死**。三条红线：(1) 绝不 100 条同时显示；(2) 绝不恒定满格红（必须可见掉血）；(3) 每条必须是“完整血条”（drains 整个 1%，不是 1/100 宽的小格）。每次改完 curl 验证 `bossBarFillInner.style.width` 由 `_remain` 驱动（非 '0%' 也非 '100%'）且 `_triggerBossBarSwap` 在 chunk 递增时触发。
